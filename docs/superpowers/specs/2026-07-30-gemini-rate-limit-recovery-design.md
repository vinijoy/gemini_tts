# Gemini 분당 한도 자동 복구 설계

## 1. 문제와 근거

결제가 연결된 Gemini API 프로젝트에서도 모델별 요청 한도는 유지된다. 확인된 429 응답은 결제 실패나 무료 티어 일일 한도가 아니라 다음 제한을 가리킨다.

- 모델: `gemini-3.1-flash-tts-preview`
- 범위: 프로젝트·모델별 분당 요청 수
- 할당량 ID: `GenerateRequestsPerMinutePerProjectPerModel`
- 현재 한도: 분당 10회
- Google 권장 재시도 시간: 오류의 `RetryInfo.retryDelay`에 포함된 약 35~57초

기존 서버는 모든 429 오류를 즉시 사용자에게 반환한다. 따라서 한도가 곧 복구되는 일시적인 분당 제한도 사용자가 직접 기다렸다가 다시 생성해야 한다.

## 2. 목표

음성 데이터 전송이 시작되기 전에 분당 요청 한도에 도달하면 Google이 반환한 재시도 시간만큼 서버가 자동으로 기다린 뒤 동일한 TTS 요청을 한 번만 다시 시도한다. 결제 또는 일일 할당량 문제는 자동 재시도하지 않고 즉시 정확한 한국어 해결 안내를 반환한다.

## 3. 선택한 접근

### 권장안: `RetryInfo` 기반의 선택적 자동 재시도

429 오류의 전체 원인 체인에서 다음 정보를 추출한다.

- 할당량 종류
- Google이 제공한 재시도 지연 시간
- 일일 무료 티어 제한 여부

프로젝트·모델별 분당 제한이며 유효한 재시도 시간이 있는 경우에만 한 번 자동 대기한다. 모든 요청에 고정 간격을 적용하지 않으므로 정상 요청의 시작 속도에는 영향을 주지 않는다.

### 검토했지만 선택하지 않은 방식

- 모든 생성 요청을 6초 이상 간격으로 직렬화: 단일 서버에서는 분당 10회를 예방할 수 있지만 정상 요청도 불필요하게 느려지고 여러 서버 인스턴스에서는 완전한 보장이 되지 않는다.
- Google에 한도 상향 신청: 장기적인 선택지는 될 수 있으나 승인 여부가 불확실하고 비용 범위를 바꿀 수 있어 앱 내부의 오류 복구를 대신하지 못한다.

## 4. 서버 동작

1. Gemini 스트림 시작 전 429 오류가 발생하면 원인 체인을 분석한다.
2. 무료 티어 일일 제한이면 즉시 `429` JSON 응답을 반환한다.
3. 분당 제한이면 `RetryInfo.retryDelay` 또는 오류 메시지의 `Please retry in ...s` 값을 읽는다.
4. 재시도 시간은 음수나 비정상적으로 긴 값의 영향을 막기 위해 1초 이상, 65초 이하 범위에서만 허용한다.
5. 유효한 분당 제한이면 요청 및 응답 스트림의 취소 신호를 감시하면서 지정 시간만큼 기다린다.
6. 같은 TTS 요청을 한 번만 다시 시도한다.
7. 재시도도 429이면 더 기다리지 않고, 잠시 뒤 다시 시도하라는 한국어 오류와 권장 대기 시간을 반환한다.

기존의 일반 네트워크 및 `OTHER` 종료 재시도 정책과 분당 한도 재시도 횟수는 별도로 관리한다. 분당 제한 대기는 일반 오류 재시도 예산을 소비하지 않으며, 한도 재시도는 최대 한 번이다.

## 5. 스트리밍 안전성

자동 대기와 재시도는 첫 PCM 바이트가 브라우저로 전달되기 전에만 수행한다. 이미 오디오 전송이 시작된 뒤에는 동일 원고를 다시 생성하거나 두 음성을 이어 붙이지 않는다. 이 원칙으로 중복 발화와 예기치 않은 언어 혼합을 방지한다.

사용자가 브라우저 요청을 취소하거나 스트림을 닫으면 대기 타이머와 진행 중인 Gemini 요청을 즉시 중단한다.

## 6. 사용자 안내

정상적으로 자동 복구되면 사용자는 기존과 동일하게 생성 중 상태를 본 뒤 스트리밍 재생을 듣는다. 별도의 경고를 표시하지 않는다.

자동 복구가 불가능한 경우에는 오류 종류를 구분한다.

- 일일 무료 티어 제한: 결제와 할당량 설정 또는 초기화 시점을 확인하도록 안내
- 분당 제한 반복: 잠시 뒤 다시 시도하도록 안내하고, 확인된 경우 권장 대기 초를 포함
- 기타 429: 일시적인 요청 제한으로 안내

API 키, 프로젝트 번호, 결제 정보와 같은 민감한 값은 로그나 사용자 오류에 포함하지 않는다.

## 7. 테스트 전략

테스트 우선 방식으로 다음을 검증한다.

- 일일 무료 티어 429는 기다리거나 재시도하지 않는다.
- 분당 429의 구조화된 `retryDelay`를 읽어 한 번 기다린 뒤 성공한다.
- 구조화된 값이 없으면 `Please retry in ...s` 메시지를 사용한다.
- 비정상적이거나 65초를 초과하는 지연은 자동 재시도하지 않는다.
- 두 번째 분당 429 뒤에는 재시도하지 않는다.
- 자동 대기 중 요청 취소가 즉시 전파된다.
- 첫 오디오 청크 이후 오류는 기존과 같이 재시도하지 않는다.
- 전체 서버·UI 테스트와 린트 및 프로덕션 빌드가 통과한다.

## 8. 문서와 버전

구현 시 PRD와 README의 기존 “429를 재시도하지 않는다” 설명을 선택적 자동 복구 정책으로 갱신한다. 하위 호환되는 오류 복구 개선이므로 패치 버전을 `0.2.5`로 올린다.

## 9. 제외 범위

- Google AI Studio에서 한도 상향 신청 제출
- 결제 수단이나 지출 한도 변경
- 여러 서버 인스턴스가 공유하는 중앙 요청 큐
- 첫 PCM 전송 이후의 TTS 재생성
