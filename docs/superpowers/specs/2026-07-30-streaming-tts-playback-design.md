# 스트리밍 TTS 재생 설계

## 1. 목표

음성 생성 요청 후 Gemini가 반환하는 오디오 청크를 브라우저에 즉시 전달하여, 전체 생성이 끝나기 전부터 자동으로 재생한다. 생성 중에는 사용자가 재생을 다시 시작할 수 없도록 다시 듣기 버튼과 다운로드 기능을 비활성화하고, 전체 음성이 완성된 뒤에만 다시 듣기와 다운로드를 허용한다.

## 2. 사용자 경험

1. 사용자가 텍스트를 입력하고 `음성 생성 시작` 버튼을 누른다.
2. 기존 음성, 완료 메시지, 다운로드 링크와 재생 상태를 즉시 초기화한다.
3. 첫 오디오 청크가 도착하면 별도 조작 없이 자동 재생한다.
4. 생성 중에는 현재 들어오는 음성만 순서대로 재생하며 `다시 듣기` 버튼과 다운로드 버튼은 비활성화한다.
5. 서버의 스트림 수신이 끝나면 누적한 전체 PCM 데이터로 WAV 파일을 만든다.
6. 생성 완료 상태를 안내하고 `다시 듣기` 버튼과 다운로드 버튼을 활성화한다.
7. `다시 듣기`를 누르면 완성된 WAV 음성을 처음부터 재생한다.

스크린리더에는 다음 상태 변화를 `aria-live` 영역으로 전달한다.

- 음성 생성 및 스트리밍 재생 시작
- 음성 생성 중
- 음성 생성 완료 및 다시 듣기 가능
- 오류 발생 및 해결 안내

## 3. 서버 구조

Next.js Route Handler는 `@google/genai`의 `generateContentStream()`을 사용한다. Gemini의 각 응답에서 `inlineData.data`를 추출하고 Base64를 바이너리 PCM 청크로 변환한 뒤, Web Streams API의 `ReadableStream<Uint8Array>`를 통해 클라이언트로 즉시 전달한다.

응답은 원시 PCM 스트림으로 취급하며 다음 메타데이터를 HTTP 헤더에 명시한다.

- 콘텐츠 유형: 범용 바이너리 스트림(`application/octet-stream`)
- 오디오 인코딩: `PCM_S16LE`
- 샘플레이트: 24,000Hz
- 채널: 모노
- 콘텐츠 스니핑 방지
- 중간 캐시 및 변환 방지

전체 길이를 생성 전에 알 수 없으므로 `Content-Length`와 완성형 WAV 헤더는 스트리밍 응답에 포함하지 않는다. 표준 `audio/L16`은 빅엔디언 PCM을 뜻하므로 리틀엔디언인 Gemini 원본에는 사용하지 않는다. WAV 포장은 전체 데이터를 받은 클라이언트가 완료 시점에 수행한다.

Gemini 호출 또는 첫 유효 오디오 청크 수신 전에 실패하면 기존 재시도와 JSON 오류 응답을 적용한다. 첫 오디오 청크 이후 발생한 오류는 스트림을 오류 상태로 종료하고, 클라이언트가 불완전한 결과물을 다시 듣기나 다운로드에 사용하지 못하게 한다. 소비자가 스트림을 취소하면 서버는 먼저 Gemini 요청을 abort하여 대기 중인 네트워크 읽기를 깨운 뒤 iterator를 정리한다.

## 4. 클라이언트 재생 구조

브라우저는 `fetch()` 응답의 `ReadableStream`을 직접 읽는다. 오디오 재생은 Web Audio API를 사용한다.

각 PCM 청크에 대해 다음 순서로 처리한다.

1. 청크를 전체 파일 생성용 누적 목록에 보관한다.
2. 16비트 리틀엔디언 정수 샘플을 `AudioBuffer`용 부동소수점 샘플로 변환한다.
3. 이전 청크의 종료 시각 뒤에 이어지도록 `AudioBufferSourceNode.start()` 시각을 예약한다.
4. 첫 청크는 가능한 즉시 자동 재생하고 이후 청크는 예약된 시각에 연속 재생한다.

네트워크 변동으로 다음 청크가 늦게 도착하면 이미 재생된 구간 뒤의 가장 이른 가능한 시점에 이어서 재생한다. 청크 간 교차 페이드나 임의의 무음 생성은 이번 범위에 포함하지 않는다.

스트림이 정상 종료되면 누적 PCM을 하나로 합치고 24kHz, 16비트, 모노 WAV 헤더를 붙여 `Blob` URL을 만든다. 이 URL은 완성 후 다시 듣기와 다운로드에 공통으로 사용한다.

## 5. 상태 모델과 UI

클라이언트 상태는 다음 세 단계로 구분한다.

- `idle`: 생성 전 또는 오류 후 상태
- `streaming`: 서버 청크를 수신하면서 자동 재생하는 상태
- `complete`: 전체 WAV 생성이 끝나 다시 듣기와 다운로드가 가능한 상태

`streaming` 상태에서는 입력, 음성 선택, 감정 태그, 스타일 입력과 생성 버튼을 기존과 같이 비활성화한다. 결과 영역은 스트리밍 시작 시 표시하되 진행 상태와 비활성화된 `다시 듣기` 버튼을 제공한다. 다운로드 역시 비활성 상태임을 시각적·의미적으로 명확히 표시한다.

`complete` 상태가 된 뒤 `다시 듣기` 버튼과 다운로드 링크를 활성화한다. 다시 듣기는 완성된 WAV 파일을 처음부터 재생하며, 스트리밍 재생에 사용한 예약 큐와 독립적으로 동작한다.

## 6. 자원 정리

새 생성 시작, 컴포넌트 해제 또는 오류 발생 시 다음 자원을 정리한다.

- 예약했지만 아직 끝나지 않은 `AudioBufferSourceNode`
- Web Audio 컨텍스트
- 이전 완성 음성의 Object URL
- 누적 PCM 청크와 재생 예약 시각

비동기 요청이 오래 걸리는 동안 새 요청이 중복 실행되지 않도록 기존 `isLoading` 보호 로직을 유지한다.

## 7. 오류 처리

- 응답 본문이 없거나 PCM 청크가 하나도 없으면 생성 실패로 처리한다.
- Base64 형식과 패딩을 엄격히 검증하고, 빈 디코딩 결과나 최종 홀수 바이트 PCM은 생성 실패로 처리한다.
- 잘못된 길이의 PCM 청크가 들어오면 마지막 불완전 샘플 바이트를 다음 청크와 결합하여 샘플 경계를 보존한다.
- 스트림 도중 오류가 발생하면 이미 들린 부분이 있더라도 완성 상태로 전환하지 않는다.
- 오류 발생 후 다시 듣기와 다운로드는 비활성화하고, 사용자가 새 요청을 시작할 수 있도록 입력과 생성 버튼을 복구한다.
- 서버 오류는 가능한 범위에서 원인과 확인할 항목을 포함한 한국어 메시지로 표시한다.

## 8. 테스트 전략

테스트 우선 방식으로 다음 동작을 검증한다.

### 서버

- Gemini의 여러 오디오 응답 청크가 순서대로 바이너리 응답에 전달된다.
- 빈 응답은 정상 완료로 오인하지 않는다.
- 스트리밍 응답에 필요한 PCM 및 캐시 방지 헤더가 포함된다.

### 클라이언트 오디오 유틸리티

- 분할된 PCM 바이트가 샘플 경계를 보존하며 변환된다.
- PCM 샘플이 올바른 부동소수점 범위로 변환된다.
- 누적 PCM으로 생성한 WAV 헤더와 데이터 길이가 정확하다.
- 청크 재생 시작 시각이 앞선 청크 뒤에 연속으로 예약된다.

### UI

- 생성 중 다시 듣기와 다운로드가 비활성화된다.
- 첫 청크 수신 시 자동 재생이 시작된다.
- 스트림 완료 전에는 완성 상태가 노출되지 않는다.
- 정상 완료 후 다시 듣기와 다운로드가 활성화된다.
- 오류 시 불완전한 음성의 다시 듣기와 다운로드가 활성화되지 않는다.
