# 상태 확인 API 설계

> 이 문서는 작성 당시의 계획·조사 기록이다. 현재 제품 범위는 [PRD](../../../PRD.md)를 따르며, 아래 계획이나 검증 상태를 현재 구현·실기 수용 완료로 해석하지 않는다.

## 목표

웹 애플리케이션 프로세스와 Next.js 라우팅이 요청에 응답할 수 있는지 외부 상태 확인 도구가 저비용으로 확인할 수 있게 한다.

## API 계약

- 경로: `GET /api/health`
- 성공 상태: `200 OK`
- 성공 본문: `{"status":"ok"}`
- 콘텐츠 유형: JSON

응답에는 애플리케이션 버전, 서버 시각, 환경변수 또는 API 키 상태를 포함하지 않는다. Gemini API도 호출하지 않는다. 이 엔드포인트는 외부 의존성 준비 상태가 아니라 웹 프로세스의 생존 상태만 나타낸다.

## 구현

`src/app/api/health/route.ts`에 인수 없는 `GET` Route Handler를 추가한다. 설치된 Next.js 16.2.12 문서가 안내하는 Web `Response.json()`을 그대로 사용한다. Next.js 16의 Route Handler는 기본적으로 캐시되지 않으므로 별도 동적 렌더링 설정이나 캐시 헤더를 추가하지 않는다.

새 의존성, 공용 헬퍼, 설정 옵션은 만들지 않는다.

## 오류 처리

상태 확인에는 실패 가능한 외부 작업이 없다. 프레임워크가 응답을 만들지 못하는 수준의 오류는 Next.js의 기존 오류 처리에 맡긴다.

## 검증

Route Handler를 직접 호출하는 단위 테스트 한 개로 다음을 검증한다.

- 상태 코드가 `200`이다.
- JSON 본문이 정확히 `{"status":"ok"}`이다.
- `content-type`이 JSON을 나타낸다.

TDD 순서로 먼저 누락된 모듈 때문에 테스트가 실패하는 것을 확인한 뒤 최소 구현을 추가한다. 이후 전체 테스트, ESLint, 프로덕션 빌드를 실행한다.

## 참고 문서 보존
