# 장문 TTS 연속 생성 및 재생 음질 일치 설계

## 1. 문제

- 긴 원고를 한 번의 Gemini TTS 요청으로 생성하면 약 1분대에서 발화 도중
  종료될 수 있다.
- 현재 서버는 Gemini 응답의 `finishReason`을 확인하지 않으므로 출력 한도에
  도달한 결과도 정상 완료된 PCM 스트림으로 전달한다.
- 생성 중 재생은 Web Audio를 사용하지만 완료 후 다시 듣기는 HTML
  `<audio>` 요소를 사용한다. 두 경로가 달라 동일한 PCM도 브라우저의
  디코딩·리샘플링 경로에 따라 음색이 다르게 들릴 수 있다.

## 2. 목표

1. 긴 원고 전체를 발화 중간 잘림 없이 하나의 연속 PCM 스트림으로 제공한다.
2. 생성 중 재생과 완료 후 다시 듣기가 같은 PCM과 같은 Web Audio 경로를
   사용하게 한다.
3. 다운로드 파일은 스트리밍에 사용한 PCM을 그대로 담은 24kHz, 16비트,
   모노 WAV로 유지한다.
4. 일부 조각이 출력 한도, 안전 정책, 네트워크 오류 등으로 불완전하게
   종료되면 완성본으로 표시하지 않고 한국어 오류를 전달한다.

## 3. 검토한 접근

### 접근 A: 비정상 종료만 감지

`finishReason`이 정상 완료가 아니면 오류를 반환한다. 잘린 파일을 완료로
표시하지 않는 장점은 있지만 장문 원고를 생성할 수 없으므로 목표를
충족하지 못한다.

### 접근 B: 브라우저에서 원고 분할

클라이언트가 여러 API 요청을 순차 실행한다. 구현 위치가 화면 상태와
결합되고, 다른 API 소비자가 동일한 보호를 받지 못하며, 요청별 오류와
취소 처리가 복잡해진다.

### 접근 C: 서버에서 문장 경계 분할 후 연속 스트리밍

서버가 원고를 문장 경계로 나누고 조각별 Gemini 스트림을 순차 소비해
하나의 PCM 응답으로 전달한다. API 소비자는 기존처럼 단일 응답만 읽으면
되고, 모든 재생·다운로드 경로가 같은 바이트를 사용한다.

**선택:** 접근 C. 장문 생성 책임과 Gemini 종료 검증을 서버 경계에
집중시킬 수 있어 가장 안정적이다.

## 4. 서버 설계

### 4.1 원고 분할

- 공백을 포함한 원문 순서를 보존한다.
- 문장 종결 부호(`.`, `!`, `?`, `。`, `！`, `？`) 뒤의 공백을 우선
  경계로 사용한다.
- 한 문장이 권장 크기를 넘으면 쉼표·줄바꿈·공백 순서로 더 작은 경계를
  찾는다.
- 기본 최대 조각 크기는 800자다. 이는 몇 분 이상 생성할 때 품질이
  흔들릴 수 있어 작은 원고로 나누라는 Gemini 공식 권고보다 보수적인
  값이며, 요청 수가 과도하게 늘지 않는 균형값이다.
- 빈 문자열 조각은 생성하지 않으며, 조각을 다시 연결했을 때 공백을
  제외한 발화 텍스트가 유실되지 않아야 한다.

### 4.2 연속 생성

- 각 조각은 동일한 음성, 스타일 지시, 모델 설정으로 순차 요청한다.
- 한 조각의 오디오 스트림이 정상 완료된 뒤 다음 조각 요청을 시작한다.
- 각 응답의 모든 후보와 part에 있는 PCM 청크를 원래 순서대로 전달한다.
- 조각 사이에 별도 무음이나 음량·필터 처리를 삽입하지 않는다.
- 사용자가 응답을 취소하면 현재 Gemini 요청을 중단하고 이후 조각은
  생성하지 않는다.

### 4.3 완료 판정과 오류

- 후보의 `finishReason`이 비어 있거나 `STOP`이면 정상으로 간주한다.
- `MAX_TOKENS`를 포함한 그 밖의 종료 사유는 해당 조각의 불완전 종료로
  처리한다.
- 첫 바이트 전 실패는 기존 재시도 정책을 적용한다.
- 일부 PCM이 이미 전달된 뒤 실패하면 스트림을 오류로 종료한다. 브라우저는
  부분 WAV를 만들거나 완료 상태로 전환하지 않는다.
- 오류 메시지는 조각 번호와 재시도 안내를 포함하되 원고 내용은 로그나
  응답에 노출하지 않는다.

## 5. 클라이언트 재생 설계

- 생성 중 도착한 PCM은 기존처럼 `StreamingPcmPlayer`에 예약한다.
- 완성 시 누적 PCM 바이트를 메모리에 보관한다.
- 다시 듣기는 HTML `<audio>`가 아니라 새 `StreamingPcmPlayer`에 완성
  PCM 샘플 전체를 넣어 재생한다.
- 다시 듣기 시작 전 아직 남아 있는 스트리밍 플레이어를 닫아 중복 재생을
  막는다.
- 새 생성, 컴포넌트 해제, 재생 전환 시 플레이어와 PCM 참조를 정리한다.
- WAV 다운로드는 동일한 누적 PCM을 `createWavBlob`으로 감싼 결과를
  사용한다. 리샘플링, 압축, 이퀄라이징은 하지 않는다.

## 6. 공개 테스트 경계

### `POST /api/tts`

- 짧은 원고는 한 번만 요청한다.
- 긴 원고는 문장 경계의 여러 요청으로 나뉘고 PCM은 요청 순서대로 하나의
  응답에 결합된다.
- 후속 조각의 비정상 `finishReason`은 성공 완료가 아니라 스트림 오류다.
- 소비자 취소가 현재 요청과 남은 조각 생성을 모두 중단한다.

### `StreamingPcmPlayer`

- 생성 중 청크와 완성 PCM 재생 모두 24kHz PCM16을 같은 변환 경로로
  예약한다.
- 재생 종료·교체 시 예약된 소스와 AudioContext를 안전하게 정리한다.

### 화면

- 완료 후 다시 듣기가 저장된 PCM을 Web Audio 플레이어로 재생한다.
- 다운로드 WAV 본문이 저장 PCM과 바이트 단위로 동일하다.
- 부분 스트림 오류 시 완료 UI와 다운로드 링크를 표시하지 않는다.

## 7. 범위 밖

- 조각 사이 음성 억양을 후처리로 보정하는 기능
- PCM 리샘플링 또는 고역 강조 필터
- 생성 결과의 서버 저장 및 재개
- 여러 조각 병렬 생성
