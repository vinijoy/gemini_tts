# 일괄 생성 제거와 목소리 제작·관리 UI 정리

## 범위와 실행
사용자 요청: 일괄 생성 기능 제거, 음성 생성 UI의 개선을 제작·관리 탭에 적용.
기본 quick: discussion/research/별도 checker/verifier 생략. skill adapter의 직접 실행 경로를 사용한다. Codex single-agent isolation gate의 orchestrator-worktree → none 순차 규칙 적용. 현재 clean 작업 트리에서 진행하고 원격 push/배포/원격 작업 삭제는 하지 않는다.

## 작업 1 — 일괄 생성 제거
- page의 batch 탭·패널·안내, BatchPanel, batches API 3개, gemini-batches와 전용 테스트 삭제.
- 전용 JSONL 업로드와 상태 레이블 제거. 음성 합성·목소리 CRUD 공통 기능은 보존.
- 기존 batch 전용 UI 테스트 제거, 공유 탭·초안·스트림·숨은 초점 회귀는 두 탭으로 수정.
- README 현재 지원 범위 갱신. 과거 계획·실행 증거는 보존.
- 검증: 앱 탭 정확히 2개, batch DOM 없음, 소스 참조 제거, build의 API 목록에서 batches 없음.

## 작업 2 — 제작·관리 UI
- 화면과 DOM을 제작 방식·모델 → 이름·언어·성별 → 설명/녹음·동의 → 생성·결과 → 저장 관리 순서로 맞춘다.
- 생성 탭의 번호 있는 h2, 이름 있는 section, fieldset, 간격과 강조 버튼을 적용한다.
- 레이블과 도움말 연결, 제작 방식에 맞는 설명/녹음 입력만 노출한다.
- TabSelect·상위 제어 상태·파일 DOM·hidden/inert 검사 유지.
- 생성 결과 미리 듣기·선택은 결과 구역, ID 조회·삭제는 관리 구역에 배치한다.
- 검증: 두 제작 방식의 제목/DOM/Tab 순서, 탭 왕복 초안·첨부·선택 보존, 제작/조회/삭제 및 비동기 초점 회귀.

npm test, lint, tsc, production build와 diff 검사. 실제 유료 생성·VoiceOver 발화는 별도 미수행으로 기록한다. 코드 atomic commit 후 SUMMARY·STATE·ui-followup 기록, 변경 API/구조에 대한 최소 맵 갱신, 문서 commit. ROADMAP 및 기존 수용 상태를 완료로 변경하지 않는다.
