# Roadmap: Gemini TTS Web UI

## Overview

기존 앱에서 Gemini 3.8 두 모델로 대본을 재생·저장하는 흐름을 먼저 완성하고, 맞춤 목소리·두 화자·출력 설정·처리 등급·Batch를 연결한 뒤 접근성과 검증 근거를 확인한다. 이번 로드맵은 요청한 기존 앱 업데이트의 범위이며 계정·생성 이력·BGM·배포를 추가하지 않는다.

**Project mode:** MVP
**Granularity:** coarse
**Created:** 2026-10-11

구현은 사용자가 승인한 `$gsd-quick` 작업으로 별도 진행한다. quick 완료는 아래 단계나 실기 수용 완료를 의미하지 않으며, 각 단계는 성공 기준과 남은 제약을 별도로 확인한 후 상태를 변경한다.

## Phases

- [ ] **Phase 1: 3.8 기본 합성과 공식 목소리 선택** - 두 모델과 공식 목소리로 대본·연출을 보존하여 안전하게 재생·저장한다.
- [ ] **Phase 2: 맞춤 목소리와 전체 합성 흐름** - 맞춤 목소리·두 화자·출력·처리 등급·Batch를 실제 사용자 흐름으로 연결한다.
- [ ] **Phase 3: 접근성과 검증 근거 수용** - 키보드·스크린리더 조작과 기능별 검증 상태를 확인하고 실제 사용 판단의 근거를 남긴다.

## Phase Details

### Phase 1: 3.8 기본 합성과 공식 목소리 선택

**Goal**: 사용자는 Gemini 3.8 Flash TTS와 Flash-Lite TTS에서 공식 목소리를 골라 대본과 연출을 보존한 음성을 재생하고 저장할 수 있다.
**Depends on**: Nothing (first phase)
**Requirements**: TTS-01, TTS-02, TTS-03, VOICE-01, VOICE-06, AUDIO-01, SAFE-01
**Success Criteria** (what must be TRUE):

1. 사용자는 두 3.8 모델 중 하나를 선택하고 대본과 문장형 연출을 각각 입력하며, 공식 인라인 발성·휴지 태그와 대본 원문을 보존하여 합성할 수 있다. 연출이 낭독 대본에 섞이지 않는다.
2. 사용자는 기본 30개와 확장 라이브러리 목소리를 공식 언어·지역·성별 표현으로 찾고 페이지를 이동하여 선택할 수 있다. 조회 실패나 없는 메타데이터는 추정값 대신 확인 가능한 상태로 안내된다.
3. 사용자는 `GEMINI-TTS-VOICES.md`에서 언어·지역 → 성별 표현 → 이름 순으로 목소리를 찾고, 출처·수집 범위·미확인 정보를 확인할 수 있다.
4. 사용자는 생성 중 음성을 듣고 취소할 수 있으며, 성공적으로 완료된 음성을 다시 재생하거나 WAV로 저장할 수 있다. 부분 생성 실패는 완성 음성으로 표시되지 않는다.
5. 사용자는 잘못된 입력·요청 상한·업스트림 실패에 대해 한국어 안내를 받고 네트워크 작업을 중단할 수 있다. 응답과 화면에는 API 키나 외부 오류 원문이 노출되지 않는다.

### Phase 2: 맞춤 목소리와 전체 합성 흐름

**Goal**: 사용자는 공식 지원 범위에서 맞춤 목소리를 만들고 두 화자·오디오 출력·처리 등급·Batch를 선택하여 원하는 방식으로 음성을 생성하고 회수할 수 있다.
**Depends on**: Phase 1
**Requirements**: TTS-04, VOICE-02, VOICE-03, VOICE-04, VOICE-05, AUDIO-02, SERVICE-01, SERVICE-02, BATCH-01, BATCH-02, BATCH-03, BATCH-04
**Success Criteria** (what must be TRUE):

1. 사용자는 설명 기반 Design, 공식 Remix, 권한 있는 참고 녹음을 이용한 Replication으로 목소리를 만들고 미리 들은 뒤 합성에 사용할 수 있다. 동의·녹음 검증·저장 여부·수명 제한을 확인하고 지원되는 조회·관리 동작을 명시적으로 실행할 수 있다.
2. 사용자는 두 화자의 목소리와 턴별 연출을 지정하여 대본 순서가 유지되는 음성을 얻을 수 있으며, 기본 목소리와 맞춤 목소리 조합에 따른 공식 제약을 안내받는다.
3. 사용자는 공식 지원 WAV, L16, μ-law, A-law와 지원 샘플레이트를 선택하며, 결과의 표시 형식·재생·다운로드 내용이 선택과 일치한다.
4. 사용자는 Standard·Flex·Priority의 비용·대기 차이를 알고 처리 등급을 선택하며, 요청 등급과 확인된 실제 처리 등급을 구분할 수 있다. 등급 미확인·강등·실패가 숨겨지거나 자동 유료 재호출로 대체되지 않는다.
5. 사용자는 여러 TTS 요청을 Batch로 제출하고 목록·식별자로 다시 열어 진행 상태를 확인하며, 지원되는 취소·삭제·내부 우선순위 조정을 명시적으로 실행할 수 있다. 완료 후 요청별 성공 음성을 재생·WAV 저장하고 실패 항목을 식별하며, inline·파일 결과 모두 원래 요청과 대응된다.

**Plans**: TBD
**UI hint**: yes

**Completion constraint**: 공개 요청 스키마가 확인되지 않은 Remix는 `VOICE-03`의 열린 차단 항목이다. Design에 설명을 다시 넣는 동작을 Remix로 대체하거나 기능을 임의 이월하지 않는다. 차단 안내만 구현한 상태에서는 해당 요구사항과 이 단계 전체를 완료로 표시하지 않는다.

**Scope boundary**: Batch 제출은 제한된 inline 요청과 polling으로 완결한다. 대용량 JSONL 입력 업로드·webhook 서버는 별도 제품 확장으로 만들지 않으며, 선택한 경로와 미구현 여부를 기능별 표에 명시한다. 파일 기반 Batch 결과 회수는 지원 범위다. Batch 내부 우선순위와 Priority 처리 등급은 별개다.

### Phase 3: 접근성과 검증 근거 수용

**Goal**: 사용자는 새 합성 기능을 키보드와 스크린리더로 조작하고, 공식 지원 범위와 자동·실제 사용 검증 결과를 구분하여 기능의 사용 가능 상태를 판단할 수 있다.
**Depends on**: Phase 2
**Requirements**: A11Y-01, DOC-01, TEST-01
**Success Criteria** (what must be TRUE):

1. 사용자는 새 입력·목소리 선택·두 화자 편집·출력 및 처리 등급 설정·Batch 작업을 키보드로 조작하고, 레이블·진행 상태·오류를 스크린리더로 확인할 수 있다. 미수행 실기와 관찰된 문제는 따로 확인할 수 있다.
2. 사용자는 보관된 공식 원문·버전과 기능별 표에서 각 기능의 구현·검증·제약·차단 사유를 확인할 수 있다. 앱의 자체 제한, 공식 제한, 대체 구현 경로와 미지원 기능이 구분된다.
3. 사용자는 모델·요청·화자·목소리·오디오·처리 등급·Batch와 기존 취소·오류 복구의 회귀 검사 결과를 확인할 수 있다. 통과한 mock 검사와 실제 API 호출·한국어 음성 청취·스크린리더 실기는 별도로 기록되어 미확인 상태를 통과로 오해하지 않는다.

**Acceptance boundary**: 유료 호출을 자동 검증 목적으로 실행하지 않는다. 실제 API 권한·카탈로그 접근·음성 청취·스크린리더 실기에서 미확인인 항목은 열린 상태로 보존하고, 자동 검사만으로 실제 사용 수용을 완료 처리하지 않는다.
